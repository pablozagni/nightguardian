# NightGuardian Ingest Protocol — v1

Status: **draft until collector v0.1 is tagged**, then stable (additive changes only).

This document is the single source of truth for every SDK. If you can read this, you can write an SDK.
Machine-readable schema: [`event.v1.schema.json`](event.v1.schema.json). Examples: [`examples/`](examples/).

## 1. Transport

```
POST {collector_url}/api/v1/ingest
Authorization: Bearer {project_token}
Content-Type: application/json
Content-Encoding: gzip            (recommended; identity also accepted)
User-Agent: {sdk.name}/{sdk.version}
X-NightGuardian-Dry-Run: 1        (optional: validate only, store nothing)
```

- HTTPS strongly recommended. The collector does not require it (for local dev) but SDKs must warn on `http://` in production.
- Limits: 1 MB compressed, 5 MB uncompressed, 100 events per request, 256 KB per event after encoding.
- Recommended SDK timeouts: connect 1 s, total 2 s.

## 2. Request body

```json
{
  "sent_at": "2026-10-17T13:45:12.345Z",
  "sdk": { "name": "nightguardian-laravel", "version": "2.0.0" },
  "events": [ { ...event }, { ...event } ]
}
```

## 3. Event envelope (common to all types)

| Field | Type | Req | Notes |
|---|---|---|---|
| `id` | string (UUID v4) | ✅ | Generated by the SDK. Used for idempotency: re-sending is safe. |
| `type` | string | ✅ | `exception`, `log`, `job_failed`, `schedule_failed`, `slow_request`, `slow_query`, `deploy`, `feedback`, `test` |
| `timestamp` | string (RFC 3339, UTC, ms) | ✅ | When it happened, not when it was sent. |
| `level` | string | ✅* | PSR-3: `debug`, `info`, `notice`, `warning`, `error`, `critical`, `alert`, `emergency`. *Not required for `deploy`/`feedback`. |
| `reference` | string | – | Human code shown to end users, format `NG-XXXX-XXXX` (Crockford base32, no I/L/O/U). |
| `environment` | string | ✅ | `production`, `staging`, … (max 64) |
| `release` | string | – | Version or commit SHA (max 128) |
| `server` | string | – | Hostname (max 255) |
| `platform` | string | ✅ | `php`, `node`, `python`, `delphi`, … |
| `sdk` | object | – | Overrides the batch-level `sdk` if present |
| `fingerprint` | string[] | – | Explicit grouping parts. If present the collector hashes these instead of its own algorithm. Use `"{{ default }}"` as an element to extend the default. |
| `tags` | object<string,string> | – | Up to 20 keys, 64/200 chars. Searchable. |
| `context` | object | – | Free-form, up to 32 KB. Shown as JSON in the panel. |
| `user` | object | – | `{ "id": "123" }`. Optional `email`, `name` only if the app opts in. |
| `request` | object | – | See §4.1 |
| `runtime` | object | – | `{ "name": "php", "version": "8.3.12", "framework": "laravel", "framework_version": "12.4.0", "os": "Linux" }` |
| `payload` | object | ✅ | Type-specific body, see §4 |

Unknown fields are ignored (forward compatibility). SDKs must not rely on them being stored.

## 4. Payloads by type

### 4.1 Shared objects

**Request**
```json
{ "method": "POST", "url": "https://app.test/invoices/12?page=2",
  "route": "invoices.update", "status_code": 500,
  "headers": { "user-agent": "...", "referer": "...", "accept": "text/html" },
  "ip": null, "duration_ms": 312 }
```
Query strings and headers must already be scrubbed by the SDK. `ip` is `null` unless the app opts in.

**Exception** (chain ordered outermost → innermost, `previous` flattened)
```json
{ "class": "Illuminate\\Database\\QueryException",
  "message": "SQLSTATE[23000]: Integrity constraint violation ...",
  "code": "23000",
  "frames": [
    { "file": "app/Http/Controllers/InvoiceController.php", "line": 88,
      "function": "update", "class": "App\\Http\\Controllers\\InvoiceController",
      "in_app": true,
      "context": { "pre": ["..."], "line": "    $invoice->save();", "post": ["..."] } }
  ] }
```
- `file` is relative to the project root when inside it; absolute otherwise.
- `in_app` = true when not under `vendor/` / `node_modules/` / framework internals.
- `context` (±5 lines) only for in-app frames, max 30 frames with context.
- `frames` are ordered **most recent first**: the first frame is where the exception was thrown, the last is the entry point (ADR 0005).
- Max 100 frames; SDKs keep the first 50 and last 50 if longer.

### 4.2 `exception`
```json
"payload": { "exceptions": [ {Exception}, {Exception} ], "handled": false }
```

### 4.3 `log`
```json
"payload": { "message": "Payment gateway timeout for order {order}", "channel": "stack",
             "context": { "order": 42 }, "exception": {Exception} | null }
```
`message` should be the template (before interpolation) when available — it groups better.

### 4.4 `job_failed`
```json
"payload": { "job": "App\\Jobs\\SendInvoice", "queue": "default", "connection": "database",
             "attempts": 3, "exceptions": [ {Exception} ] }
```

### 4.5 `schedule_failed`
```json
"payload": { "command": "php artisan invoices:sync", "expression": "*/5 * * * *",
             "exit_code": 1, "output_tail": "last 2 KB of output", "exceptions": [ ] }
```

### 4.6 `slow_request`
```json
"payload": { "duration_ms": 4810, "threshold_ms": 2000, "memory_mb": 64.2, "queries": 133 }
```
Grouped by `request.method` + `request.route`.

### 4.7 `slow_query`
```json
"payload": { "sql": "select * from invoices where customer_id = ? and date > ?",
             "duration_ms": 2350, "threshold_ms": 1000, "connection": "mysql",
             "location": { "file": "app/Reports/Sales.php", "line": 40 } }
```
`sql` must have bindings replaced by `?`. Grouped by normalized SQL.

### 4.8 `deploy`
```json
"payload": { "release": "a1b2c3d", "commit": "a1b2c3d4e5...", "branch": "main",
             "deployer": "pull.sh", "url": "https://github.com/acme/app/commit/a1b2c3d" }
```
Not grouped; listed in the panel and used for "resolved in release" and regressions.

### 4.9 `feedback`
```json
"payload": { "event_id": "<id of the original event>", "reference": "NG-7F3K-92QD",
             "comment": "I was trying to issue invoice B 0001-00001234", "email": null }
```
Max comment 2,000 chars. If the original event is unknown (not yet received), the collector keeps the
feedback and attaches it when the event arrives (matching by `event_id` or `reference`).

### 4.10 `test`
Same payload as `exception`. Stored and shown, never alerts except a one-time "connection OK" notice.

## 5. Response

`202 Accepted`
```json
{ "accepted": 2, "rejected": 1,
  "results": [
    { "id": "…", "status": "accepted", "issue": "01JAB…" },
    { "id": "…", "status": "duplicate" },
    { "id": "…", "status": "rejected", "errors": ["payload.exceptions: required"] }
  ] }
```

| Status | Meaning | SDK action |
|---|---|---|
| `202` | Processed (check per-event results) | Delete accepted/duplicate/rejected from spool. Never retry rejected. |
| `400` | Malformed body (not JSON, bad gzip) | Drop batch, log locally once. |
| `401` / `403` | Bad or revoked token | Stop sending; open circuit for 1 h; keep spooling (bounded). |
| `413` | Too large | Split batch and retry; drop single oversized events. |
| `429` | Rate limited | Respect `Retry-After`; keep spool. |
| `5xx`, timeout, DNS, TLS | Collector problem | Keep spool, open circuit breaker (see §6). |

## 6. Required SDK behavior

1. **Never throw into the host app.** Every SDK entry point catches everything.
2. **No recursion.** Errors raised while capturing/sending are never captured.
3. **Send off the critical path** (after response, background thread, shutdown hook — per platform).
4. **Spool on failure** to local storage, bounded (default 10 MB / 7 days), oldest dropped first.
5. **Circuit breaker:** after a failure, stop network attempts for 60 s, doubling up to 15 min; spool meanwhile.
6. **Drain** the spool gradually (max 1 batch per opportunity), guarded by a lock, never during a user's request if the platform allows deferring.
7. **Scrub before sending** (see [../security.md](../security.md)): passwords, tokens, secrets, cookies, `authorization`, card-like numbers.
8. Generate `id` (UUID v4) and, for user-facing errors, a `reference`.

## 7. Versioning

- New optional fields and new event `type`s may be added to v1 at any time. Collectors ignore unknown fields; SDKs must ignore unknown response fields.
- A collector receiving an unknown `type` rejects that event with `unknown_type` (SDK drops it).
- Breaking changes require `/api/v2`, an ADR, and v1 support for at least 12 months.
